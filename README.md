# 多Agent生态开发工具

一个**本地化多 Agent 协同开发工作台**：用户在网页上提出开发需求，由 7 个职责固定的 Agent 角色协作完成任务的拆解、执行、质检与交付。**纯裸机运行，无 Docker、无容器沙箱**，安全体系采用「会话/工作区目录隔离 + 操作白名单 + 高危强制人工审批 + 后端二次校验」四层约定。

- 后端：FastAPI（Python 3.12）
- 前端：原生 HTML / CSS / JavaScript（无框架、无构建工具）
- 存储：SQLite（WAL 日志库）+ 本地 numpy 向量库（长期记忆）
- 模型：全部通过 OpenAI 兼容的 `/chat/completions` 协议调用外部大模型 API

---

## ✨核心特性

以下能力全部由代码实际实现，未做任何虚构。

### 1. 七大 Agent 协同流水线
用户提交一个需求后，系统按固定链路协作：**调度规划 → 记忆检索 → 任务拆解 → 并行/串行子任务执行 → 评估校验 → 结果汇总 → 交互交付**。调度规划 Agent 扮演「队长」做全局拆解与调度，其余 Agent 为「队员」。

### 2. 队长-队员层级与冲突仲裁
- 所有队员输出必须上报队长；
- 队员之间出现信息冲突、数据不一致、结论矛盾（例如两份待删清单条目/数量不同）时，自动触发队长仲裁流程；
- 队长裁决后的结果为整条任务链路唯一基准，强制所有队员沿用；
- 仲裁思考过程通过思维链在 UI 展示，可审计。

### 3. 模型生态位自动补位
当某角色绑定的专属模型不可用时，自动按固定优先级（**DeepSeek > Qwen > GLM > Kimi**）在**本机已连通测试通过**的其他模型中选择补齐，可在设置页一键开关。该能力仅依赖已通过连通性测试的模型，不保证一定可用。

### 4. 裸机安全隔离（替代 Docker）
- **目录隔离**：所有 Agent 的文件读写/创建/修改/删除都被限制在当前选中工作区目录内，越界访问后端直接拒绝并记录安全日志；
- **能力白名单**：每个 Agent 通过能力矩阵只拥有被授予的能力，越权调用抛安全异常；
- **高危强制审批**：删除、批量修改、系统命令、外网下载等操作自动进入 `waiting_approval` 状态，人工审批通过后才执行；高危审批开关**永久开启、不可关闭**；
- **后端二次校验**：审批时必须校验审批记录存在性、`pending` 状态、会话归属、风险等级一致性、操作参数 SHA256 指纹，全部通过才放行——前端提交的 "approved=true" 不被直接信任。

### 5. 磁盘修改由后端硬编码执行
所有磁盘修改/删除动作全部由后端 Python 代码（`services/executor.py`）完成，高危动作识别完全由后端程序硬编码（`constants.HIGH_RISK_OP_SET`）判定，**不依赖大模型输出文本**；审批通过前绝不触碰磁盘，逐个执行并收集真实回执。

### 6. 长期记忆（向量库）
记忆管理 Agent 负责上下文压缩与知识沉淀：短期记忆为内存会话级，长期记忆持久化到本地向量库（numpy 精确余弦相似度检索，**90 天 TTL 自动淘汰**）。向量库异常时自动降级为仅短期记忆，系统不崩溃。

### 7. 文档与图像解析
- 文档信息 Agent：PDF / Word / Markdown / TXT / CSV / 代码文件的超长解析、信息抽取、结构化摘要、资料对比；约束为只输出「结构化摘要 + 限量引用片段」，不输出原始长文本。
- 视觉感知 Agent：仅当用户输入包含图片/截图时触发，做 UI 识别、报错截图分析、页面结构解析；只输出结构化描述，不直接生成代码。

### 8. 工作区与会话管理
- 工作区：新建、重命名、删除、添加本地文件夹（支持绝对路径探测/选择）、切换；删除工作区会连带清理其下全部会话/任务/审批记录（不可恢复，前端二次确认）。
- 会话：新建、列表、详情、删除、在会话之间移动归属。
- 每个会话拥有独立工作目录与文件守卫。

### 9. 任务执行计时器
任务提交后自动开始计时，支持暂停/恢复（审批暂停期间计时停止）、取消终止、历史记录，状态栏数据来自后端真实采集值。

### 10. 实时流式输出（SSE）
任务思考链（thinking chain）通过 SSE 逐条实时推送到前端，前端可折叠查看分步图标与连接线。

### 11. 模型 API 配置
支持配置 4 家厂商（DeepSeek、通义千问 Qwen、Kimi 月之暗面、智谱 GLM）的 API Key、Base URL、模型标识，可逐个模型测试连通性；密钥以 **AES-256-GCM 加密 + SHA256 篡改校验** 存储于本机 config 目录，明文永不返回前端。首次启动无有效配置时强制弹出 API 配置向导，至少配置一个模型并通过连通测试才能进入工作台。

### 12. 后台登录
内置管理员账号（默认 `admin` / `admin123`，bcrypt 哈希存储，文档要求首次登录后修改）。本机回环（127.0.0.1）免登录，**局域网访问强制登录**，禁止公网暴露。会话令牌由进程内随机密钥签署，TTL 12 小时。

### 13. 其他能力
- 背景：内置 3 套主题 + 自定义图片上传（后端校验：白名单扩展名 / 50MB 上限 / 禁可执行文件），持久化保存；
- 数据备份导出、错误日志查看、审批记录永久留存与清空、配置平滑迁移（schema 版本化，自动清理历史残留模型标识）。

## 🖥️系统架构

- **能力层** `backend/agents/`：7 个职责单一、绑定固定的 Agent；
- **总线层** `backend/bus/`：消息、路由、任务状态机；
- **服务层** `backend/services/`：运行时编排、审批、仲裁、执行器、模型客户端、配置、流式代理；
- **基础设施层** `backend/infrastructure/`：SQLite 日志库、文件守卫、日志、向量库、备份；
- **工具层** `backend/utils/`：常量、模型注册、路径安全、密钥、上传校验。

## 🤖七大 Agent 与模型绑定

角色 ↔ 模型绑定**固定、不可调换**（代码有断言强制校验）：

| 角色 | 模型 | 厂商 | 职责（代码声明） | 能力白名单 |
|---|---|---|---|---|
| 调度规划Agent（队长） | Qwen3.8-Max | 通义千问 | 全局大脑、任务拆解、流程管控 | dispatch, memory_write |
| 代码工程Agent | DeepSeek-Flash | DeepSeek | 代码生成、修改、调试、文件操作、命令执行 | file_write, file_delete, command, download |
| 文档信息Agent | Kimi K3 | Kimi | 超长文档解析、抽取、摘要、知识库处理 | doc_parse |
| 视觉感知Agent | Qwen3.8-Flash | 通义千问 | 截图识别、UI识别、报错看图分析 | image_parse |
| 记忆管理Agent | GLM-5.3-Flash | 智谱 | 记忆压缩、向量化、检索、归档 | memory_write |
| 评估校验Agent | GLM 5.3 | 智谱 | 质量校验、格式校验、安全校验、裁判审核 | evaluate |
| 交互交付Agent | Kimi k2.6 | Kimi | 用户对话、需求澄清、结果润色、前端展示格式化 | polish |

说明：
- 代码工程 Agent 是**唯一**持有 `file_write / file_delete / command / download` 能力的角色；
- 评估校验 Agent 是全局唯一质检/裁判/安全审核中心，最多打回校验 2 次，两次失败上报用户；
- 交互交付 Agent 只做展示层润色，交付前后做「事实一致性核查」，发现关键事实（代码块/路径/数字/报错原文）被改动则丢弃润色结果、回退使用原始文本。

## 📄安全体系

| 层级 | 机制（代码实现） |
|---|---|
| 目录隔离 | `file_guard.SessionFileGuard`：所有 Agent 文件操作仅限当前工作区目录，越界抛 `SecurityViolation` 并写安全日志 |
| 操作白名单 | `base.CAPABILITY_MATRIX`：每个 Agent 只拥有被授予的能力，越权调用抛异常 |
| 高危审批 | `approval_center`：删除/批量修改/命令/下载 → `waiting_approval`；状态机 `pending -> manual/rejected`，同一审批 ID 只裁决一次（防重放）；开关永久开启 |
| 后端二次校验 | 审批放行需校验记录存在性、pending 状态、会话归属、风险等级一致性、操作参数 SHA256 指纹 |
| 后端执行 | `executor`：所有磁盘修改由后端硬编码完成，高危识别不依赖 LLM，审批通过前不触碰磁盘 |
| 密钥 | AES-256-GCM 加密 + SHA256 篡改校验，明文不返回前端 |
| 登录 | bcrypt 哈希存储，会话令牌进程内随机密钥签署，TTL 12h |
| 上传 | 单文件 50MB 上限，扩展名白名单，禁止可执行文件，隔离到当前会话目录 |

## 🚀快速开始

要求：Python 3.12。

```bash
# 1) 安装依赖（均为普通 Python 包，无任何容器运行时）
python -m pip install -r requirements.txt

# 2) 启动服务（默认监听 0.0.0.0:5090，支持局域网访问）
python run.py

# 仅本机访问 / 换端口
python run.py --host 127.0.0.1 --port 5091

# 自定义数据根目录（默认走系统规范路径）
# Windows 下： MAE_ROOT=D:\mae python run.py

# 查看数据根目录
python run.py --show-root
```

浏览器打开 <http://127.0.0.1:5090>：

1. 首次启动检测到无有效配置 → 强制弹出「API 配置向导」；
2. 至少配置**一个**模型 API Key，并对其点击「测试连通」（接口超时 5 秒）；
3. 向导达标后才可进入工作台；未达标时后端直接拒绝（HTTP 400）。

后台登录：用户名 `admin`，初始口令 `admin123`（bcrypt 存储，请首次登录后立即修改）。本机回环免登录；局域网访问强制登录，禁止公网暴露。

数据根目录默认在系统规范路径（Windows 为 `%USERPROFILE%\.multi_agent_ecosystem\`），包含 `config / sessions / uploads / logs / vector_db` 五个子目录，启动时自动初始化。

## ⚙️配置说明

- **模型厂商**：DeepSeek（`https://api.deepseek.com`）、通义千问 Qwen（`https://dashscope.aliyuncs.com/compatible-mode/v1`）、Kimi 月之暗面（`https://api.moonshot.cn/v1`）、智谱 GLM（`https://open.bigmodel.cn/api/paas/v4`）。全部走 OpenAI 兼容 `/chat/completions` 协议。
- **模型标识**：代码里注册了各家合法标识（如 `deepseek-flash`、`qwen3.8-max`、`kimi-k3`、`glm-5.3` 等），并自动识别/清理历史遗留的旧模型标识。
- **生态位补位开关**：默认开启，可在设置页关闭；补位仅在已通过连通测试的模型中进行。
- **配置迁移**：配置文件带 schema 版本号（当前 `1.5`），升级时平滑迁移旧字段、不丢失用户自定义。

>[!warning]
>## ⚠️已知局限与缺点
>
>
>1. **依赖外部大模型 API 且需联网**：系统本身不做推理，全部调用 4 家外部厂商（DeepSeek / 通义千问 / Kimi / 智谱 GLM）的在线 API。未配置对应厂商 Key 时，绑定该厂商的角色能力不可用；离线环境下系统无法完成任务。首次启动必须配置至少一个模型>并通过连通测试。
>
>2. **角色 ↔ 模型绑定固定不可调换**：七大 Agent 与厂商/模型一一绑定，代码用断言强制校验（`ROLE_IMMUTABLE`），用户不能把某角色任意换绑到其它模型；只能整体覆盖某厂商的模型标识。
>
>3. **裸机安全是「约定式隔离」，非强隔离**：没有 Docker/容器沙箱。安全依赖「目录隔离 + 白名单 + 高危审批 + 后端二次校验」四层约定，高危命令/删除仍需人工放行；若运行环境目录权限配置不当，存在越权风险（代码已在运行路径上尽力拦截）。适合单>机、受控环境，不适合作为多租户公网服务。
>
>4. **高危操作必须人工审批、无法全自动无人值守**：审批开关永久开启、不可关闭；批量删除 ≥2 个文件即判高危，审批等待默认 30 秒超时后自动做降级决策。追求全自动 CI/CD 的流程会因人工介入而中断。
>
>5. **长期记忆为本地简易向量库**：基于 numpy 精确余弦相似度检索，非外部向量数据库服务；90 天 TTL 自动淘汰，向量库异常时自动降级为仅短期记忆。记忆规模大时检索性能有限。
>
>6. **SQLite 单机单进程设计**：WAL + 单连接 + 线程锁，适合单实例；不面向多进程/多节点横向扩展，多用户高并发不是设计目标。
>
>7. **单内置管理员账号**：仅 `admin` 一个登录账号（bcrypt 存储），无多用户、无角色/权限管理系统；会话令牌密钥在进程内随机生成，重启服务后所有会话失效需重新登录。
>
>8. **文档 Agent 不返回原始长文本**：约束为只输出「结构化摘要 + 限量引用片段」（引用 ≤200 字、总量 ≤原文 10%），需要原文全文的场景无法直接获得。
>
>9. **质量闸门有打回上限**：评估校验最多打回 2 次、代码重试最多 3 次、单任务全局迭代最多 20 次、计划再生成重试最多 1 次。复杂或易错的任务可能以「失败」终止并上报用户，不能无限自愈。
>
>10. **文件上传限制**：单文件 50MB 上限，扩展名白名单过滤，禁止可执行文件；仅支持白名单内的图片/文档/文本类型。
>
>11. **前端为原生单体**：`frontend/app.js`（约 211KB）为原生 JS 单体，无现代前端框架与工程化构建、无单元测试体系（测试文件已随本项目移除）；`backend/main.py`（约 120KB）与 `backend/services/runtime.py`（约 350KB）为超大单文件，长期>维护需注意模块拆分。
>
>12. **默认路径偏 Windows**：数据根目录默认走 Windows `%USERPROFILE%` 规范路径，跨平台部署需显式指定 `MAE_ROOT` 环境变量。
>
>13. **无独立复杂统计/报表页**：Token 统计、日志、审批记录等仅通过少量只读接口暴露，界面只展示聚合信息，无深度可视化报表。
